This thread sometimes seems to be focusing on concrete implementation disputes before agreeing on the governing principle.

There are really two separate questions: whether val_bpb still has a clean information-theoretic interpretation, and whether the contest should reward transductive adaptation to the public evaluation stream. I still think the cleanest end state is two leaderboards, for the reasons in my previous comment. But regardless of whether the final structure is a single leaderboard or a split one, this issue is logically prior: under the current evaluation protocol, the community still needs a precise criterion for when val_bpb retains a clean information-theoretic interpretation. The minimum such conditions are:

At position t, the predictive distribution p_t(.) must be a function only of the submitted artifact A and the strict prefix x_1, ..., x_{t-1}. Equivalently, it may depend only on the pre-step state s_t, where s_t itself was constructed solely from A and x_1, ..., x_{t-1}. It may not depend on x_t or any future token, on any statistic computed from future validation tokens, or on any external data or runtime side information not already encoded in A before evaluation begins.

Before x_t is scored, the submission must define a single full probability distribution over the official fixed token alphabet Σ. That is, for every token a in Σ, p_t(a) >= 0, and the probabilities must satisfy sum_{a in Σ} p_t(a) = 1. Moreover, this distribution must be the one the submission's predictive mechanism would assign if evaluated for every token a in Σ under the same pre-step state s_t. The value of p_t(a) must therefore be determined independently of which token is later realized at position t. In particular, the distribution may not be constructed by evaluating only the realized token x_t and then filling in the remaining mass by residual redistribution, background renormalization, or any other x_t-contingent completion rule. This normalization must hold over actual tokens, not merely over internal buckets, hash bins, experts, or other latent structures.

The score at position t must be computed from the pre-update probability assigned to the realized token, namely p_t(x_t). Only after that score is fixed may the runtime state be updated using x_t. Therefore the current symbol may not influence its own assigned probability, whether directly or indirectly through same-symbol adaptation, self-exclusion, or any equivalent mechanism.

Evaluation must consist of exactly one left-to-right pass over the validation sequence. No rescoring, no second pass, no retrospective revision of earlier probabilities, no selection among multiple executions based on observed validation outcomes, and no other mechanism that changes the probability assigned to a token after later tokens have been seen.
